# V4.3 Player Defeat / Battle Failure Polish SPEC（玩家失败与战斗失败打磨规格）

> 本文是 V4.3 的开发规格。V4.3 不是新玩法阶段，而是把 V4.2 的 BattleEnded Defeat（战斗失败）打磨成稳定、可观察、可测试的失败体验。

**状态：已实现（V4.3 completed）**

## 1. 目标

完成以下闭环：

```text
玩家被敌人击败
  ↓
PlayerDefeated（玩家被击败）
  ↓
BattleEnded Defeat（战斗失败）
  ↓
战斗规则停止
  ↓
UI / Canvas 明确显示失败
  ↓
Reset 后恢复可战斗状态
```

## 2. 必须实现

### 2.1 Defeat 后停止战斗规则

当 `battle.active === false` 时：

- 不推进玩家动作。
- 不推进敌人动作。
- 不启动 AutoAttack（自动普攻）。
- 不消费 Art（武技）输入。
- 不启动 EnemyAttack（敌人攻击）。
- 不继续造成 Debuff tick damage（负面状态跳伤）。

允许：

- VFX（视觉提示）继续衰减。
- UI render（界面渲染）。
- Reset（重置）。

### 2.2 Defeat Snapshot（失败状态快照）

失败后 Snapshot（状态快照）必须满足：

```js
battle.active === false
battle.result === 'Defeat'
player.dead === true
player.hp === 0
```

如果继承 V4.2.1，`finalSnapshot` 必须保留真实场景终态。

### 2.3 Reset after Defeat（失败后重置）

`resetRuntime()` 后必须满足：

```js
battle.active === true
battle.result === null
player.dead === false
player.hp === player.maxHp
target.dead === false
target.hp === target.maxHp
enemy.action === null
enemy.state === 'Idle'
```

### 2.4 UI / Canvas（界面 / 画布）

DebugPanel（调试面板）应清楚显示：

- Battle Result（战斗结果）为 Defeat。
- Player HP（玩家生命值）为 0/max + DEAD。
- Enemy action（敌人动作）停止。

Canvas（画布）应清楚显示：

- DEFEAT（失败）。
- 玩家血条为 0。
- 可选：Press R to Reset（按 R 重置）。

## 3. 必须新增 Scenario（脚本化场景）

新增或补强：

- player-defeat-stops-combat
- reset-after-defeat
- input-ignored-after-defeat

### player-defeat-stops-combat

证明：

```text
PlayerDefeated
  ↓
BattleEnded Defeat
  ↓
继续 tick 120f
  ↓
没有新的 EnemyAttackStarted / EnemyAttackHit / PlayerDamageApplied
```

### reset-after-defeat

证明：

```text
先进入 Defeat
  ↓
resetRuntime()
  ↓
battle.active === true
battle.result === null
player.dead === false
player.hp === player.maxHp
```

### input-ignored-after-defeat

证明：

```text
先进入 Defeat
  ↓
持续输入 Art / movement
  ↓
没有 ActionStarted
没有 InputConsumed
没有 EnemyAttackStarted
```
